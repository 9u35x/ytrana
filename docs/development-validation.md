# تحقق تحديث النجوم وتحسينات Ytrana

## ما تم حفظه

تطوير إضافي على المنصة الحالية: نظام نجوم 1–10 من بيانات المتابعة والنشر الحقيقية، واجهة معاينة متوافقة مع RTL على الويب والهاتف، وحماية صلاحيات قراءة تفاصيل الحساب. يحفظ هذا التحديث كذلك المصدر والاختبارات والوثائق العامة التي كانت موجودة محليًا قبل بدء تطوير النجوم؛ بما فيها وحدات الحساب والخصوصية والإشراف والوسائط ومصدر الهاتف، دون استبدالها أو إعادة ضبطها.

أُصلحت حالات مرتبطة بالميزة: ربط الويب بعميل `Api` المعرّف بـ`const` في النطاق العام، تحديث اقتراح المكافأة عند اختيار المستوى، استبعاد التجميد الدائم من المتابعين المؤهلين، معالجة بيانات جلسة محلية تالفة، سباقات الطلبات وتبديل الهوية وأخطاء الخصوصية في الهاتف، وتباين بطاقة النجوم في الوضعين الفاتح والداكن. أضيف `pytest` إلى متطلبات الاختبار كي تنفذ اختبارات الخادم فعليًا بدل الاعتماد على اكتشاف unittest غير المناسب لها.

## الاختبارات المنفذة

- الخادم: `PYTHONPATH=backend:tests python -m pytest tests -q --disable-warnings` — **77 ناجحًا**، منها 21 حالة للنجوم؛ ظهرت 343 رسالة تحذير اعتماديات/واجهات SQLAlchemy القديمة. لم تُخفَ إخفاقات.
- الويب وعقود الهاتف: تشغيل ملفات `tests/*.cjs`، بما فيها اختبارات النجوم واختبار ذاكرة المصادقة، مع اختبارات Reels الثلاث في `mobile/tests/`.
- الهاتف: `npm run typecheck` يستخدم `tsc --noEmit`. اختبار النجوم السلوكي يستخدم ترجمة TypeScript ومحاكاة دورة hooks والعناصر الأصلية دون اعتماديات جديدة.
- التحقق الساكن: `node --check` لملفات JavaScript، و`python -m compileall` للخادم، و`git diff --check`.
- متصفح محلي فعلي: تسجيل دخول حساب اختبار بقاعدة SQLite منفصلة خارج المستودع، عرض بياناته الفعلية الصفرية، ظهور عشرة أزرار، اختيار معاينة المستوى العاشر مع بقاء المستوى المكتسب 1، عرض عتبة 50 مليون و365 يومًا، وتحديث الاقتراح غير المطبق إلى 50% دون منح المستوى أو ضمان الوصول.

## ما لا تثبته الاختبارات

محاكاة الهاتف ليست اختبارًا على جهاز Android أو iPhone أو native renderer. لم يُنشأ APK/AAB/IPA جديد، ولم يُشغّل lint غير مهيأ يتطلب تثبيت إعدادات تلقائيًا. توجد حاجة إلى تجربة أجهزة فعلية قبل إصدار لاحق. هذا ليس تدقيقًا أمنيًا شاملًا أو اختبار تحميل؛ فحص حاويات الفيديو الحالي لا يعادل فحص codecs أو مكافحة البرمجيات الخبيثة.

## حماية الملفات والبيانات

لا نشر إنتاجي ولا تغيير استضافة أو حسابات إدارة أو بيانات إنتاج. لا خدمة خارجية أو رسوم أو خطة دفع جديدة، وخطط الاشتراك الثلاث لم تتغير بسبب النجوم. لا يتغير ترتيب الخلاصات؛ أي نسب أولوية معروضة موسومة بأنها غير مطبقة.

تستبعد Git وDocker ملفات البيئة الفعلية، مفاتيح توقيع Android وملفات خصائصها، قواعد البيانات، uploads، نسخ الإنتاج وتقاريرها، APK/AAB/IPA/ZIP، وملفات البناء الأصلية المولدة. تبقى قوالب `.env.example` ذات القيم الوهمية/الفارغة فقط، والمصدر والوثائق والاختبارات المناسبة. فحص الأنماط الشائعة للمفاتيح لم يجد مطابقات في الملفات المرشحة، ولا يلغي ذلك الحاجة لإبقاء الأسرار خارج المصدر مستقبلًا.

## الحفظ في GitHub

عند مراجعة الحالة كان `main` المحلي مساويًا للبعيد، دون تغييرات واردة تحتاج دمجًا. وصلت الوصلة إلى الحساب والمستودع، لكن فحص Git push التجريبي رُفض بـ403؛ لذلك توقفت محاولات الدفع دون تجاوز الإذن أو force push. التحديث محفوظ محليًا إلى حين إعادة اعتماد وصلة تسمح بكتابة محتويات المستودع أو استخدام مسار موافقة آمن. لا ينبغي وصف هذا التحديث بأنه مرفوع إلى GitHub قبل التحقق من وصول commit نفسه إلى `origin/main`.
